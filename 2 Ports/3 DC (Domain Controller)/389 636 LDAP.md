# LDAP (389 / 636)

Tags: #LDAP #DC #AD #Enumeracion #LDAPSearch #LDAPDump

## OBJETIVO

- Verificar si permite anonymous/null bind
- Enumerar usuarios, grupos y estructura del dominio
- Extraer información sensible del directorio AD
- Identificar cuentas con configuraciones débiles

## TIPS

1. **Anonymous bind → pruébalo siempre primero → muchos servidores mal configurados lo permiten**
2. **389 → LDAP sin cifrar | 636 → LDAPS con SSL → mismos comandos, diferente esquema**
3. **ldapdomaindump → genera archivos HTML navegables → más cómodo que leer ldapsearch crudo**
4. **Las descripciones de usuarios en AD → frecuentemente contienen contraseñas hardcodeadas**
5. **Con creds válidas → LDAP da más info que SMB en muchos casos**

## TOOLS

- [ldapsearch](https://linux.die.net/man/1/ldapsearch)
- [ldapdomaindump](https://github.com/dirkjanm/ldapdomaindump)
- [Impacket](https://github.com/fortra/impacket)
- [NetExec](https://github.com/Pennyw0rth/NetExec)

## 1. VERIFICAR ANONYMOUS / NULL BIND (SIN CREDENCIALES)

```bash 
# Enumerar 
❯ ldapsearch -x -H ldap://<IP> -b "DC=domain,DC=corp"   
# No requiere creds → enumerar todo el dominio con anonymous bind

# Enumerar
❯ ldapsearch -x -H ldap://<IP> -b "DC=domain,DC=corp" "(objectClass=*)"

	# distinguishedName: CN=Freddy McSorley,CN=Users...
	# description: Password set to CrabSharkJellyfish192 at user's request.
	# sAMAccountName: fmcsorley    <-- Importante  
	

# Filtrar solo por los usuarios 
❯ ldapsearch -x -H ldap://<IP> -b "DC=domain,DC=corp" "(objectClass=user)" cn | grep '^cn:' | awk -F': ' '{print $2}' > names.txt 
```

```bash
❯ ldapsearch -x -H ldap://<IP> -s base namingcontexts
# No requiere creds → verifica si anonymous bind está permitido
# Si devuelve resultados → anonymous bind habilitado → alto valor
# Devuelve el base DN del dominio (ej: DC=domain,DC=corp)

❯ nxc ldap <IP> -u '' -p ''
# No requiere creds → verifica null bind con netexec
# Más rápido para confirmar si es posible
```

### Insight

- Si anonymous bind funciona → enumerar TODO antes de pasar a otras fases
- El base DN obtenido (DC=domain,DC=corp) → usarlo en todos los comandos siguientes

## 2. DUMP COMPLETO CON LDAPDOMAINDUMP CON CREDENCIALES 

```bash
❯ ldapdomaindump -u 'domain.corp\user' -p 'passwd' <IP>
# Requiere creds → dump completo del dominio en archivos HTML/JSON/CSV
# Genera: usuarios, grupos, equipos, GPOs, políticas

❯ ldapdomaindump -u 'domain.corp\user' -p 'passwd' -o ./ldd ldap://<IP>
# Requiere creds → guardar output en directorio específico
# -o → directorio de salida

❯ python3 -m http.server 80
# Montar servidor HTTP para ver los archivos HTML generados
# Navegar a http://localhost:80 → ver toda la info de forma visual
```

### Insight

- ldapdomaindump → la forma más cómoda de ver la estructura del dominio
- Archivo `domain_users.html` → buscar descripciones con contraseñas
- Archivo `domain_groups.html` → ver quién está en Domain Admins


## 3. ENUMERACIÓN CON CREDENCIALES

```bash
❯ ldapsearch -x -H ldap://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp"
# Requiere creds válidas → enumerar todo el directorio autenticado
# -D → Distinguished Name del usuario que se autentica
# -w → contraseña
# -b → base de búsqueda

❯ ldapsearch -x -H ldap://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp" \
  "(objectClass=person)" sAMAccountName
# Requiere creds → extraer solo nombres de usuario (sAMAccountName)
# Más limpio que dumpearlo todo

❯ ldapsearch -x -H ldap://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp" \
  "(objectClass=person)" sAMAccountName description
# Requiere creds → usuarios con sus descripciones
# Las descripciones pueden contener contraseñas en claro → revisar siempre

❯ nxc ldap <IP> -u 'user' -p 'pass' --users
# Requiere creds → listar todos los usuarios del dominio
# Más rápido que ldapsearch para un listado rápido

❯ nxc ldap <IP> -u 'user' -p 'pass' --groups
# Requiere creds → listar grupos del dominio

❯ nxc ldap <IP> -u 'user' -p 'pass' --get-sid
# Requiere creds → obtener SID del dominio
# Necesario para ataques posteriores (Silver/Golden Ticket)
```


## 4. BÚSQUEDAS ESPECÍFICAS

```bash
❯ ldapsearch -x -H ldap://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp" \
  "(cn=administrator)"
# Requiere creds → info detallada de un usuario específico

❯ ldapsearch -x -H ldap://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp" \
  "(&(objectClass=person)(description=*))" description sAMAccountName
# Requiere creds → usuarios que tienen descripción → buscar passwords
# Operador & → AND → ambas condiciones deben cumplirse

❯ ldapsearch -x -H ldap://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp" \
  "(|(cn=admin)(cn=administrator))"
# Requiere creds → buscar admin O administrator
# Operador | → OR → cualquiera de las condiciones

❯ nxc ldap <IP> -u 'user' -p 'pass' --admin-count
# Requiere creds → cuentas con adminCount=1
# Históricamente privilegiadas → alto valor

❯ nxc ldap <IP> -u 'user' -p 'pass' --password-not-required
# Requiere creds → cuentas sin contraseña requerida
# Posibles targets para AS-REP Roasting

❯ nxc ldap <IP> -u 'user' -p 'pass' --trusted-for-delegation
# Requiere creds → cuentas con delegación sin restricción
# Alto valor para escalada de privilegios
```


## 5. ENUMERACIÓN DE USUARIOS CON IMPACKET

```bash
❯ impacket-GetADUsers -all domain.corp/user -dc-ip <IP>
# Requiere creds válidas → enumerar todos los usuarios del dominio
# Más limpio que ldapsearch para obtener lista de usuarios

❯ impacket-GetADUsers -all domain.corp/user -dc-ip <IP> -pwd-last-set
# Requiere creds → incluir fecha de último cambio de contraseña
# Cuentas con contraseña antigua → más probable que sea débil

❯ impacket-GetADUsers domain.corp/user -dc-ip <IP>
# Sin -all → solo usuarios activos (excluye deshabilitados)
```

## 6. LDAPS (PUERTO 636 — SSL)

```bash
❯ ldapsearch -x -H ldaps://<IP> -b "DC=domain,DC=corp"
# No requiere creds → mismo anonymous bind pero con SSL
# Cambiar ldap:// por ldaps://

❯ ldapsearch -x -H ldaps://<IP> \
  -D "cn=user,DC=domain,DC=corp" -w 'passwd' \
  -b "DC=domain,DC=corp"
# Requiere creds → enumeración autenticada por SSL

❯ ldapdomaindump -u 'domain.corp\user' -p 'passwd' ldaps://<IP>
# Requiere creds → dump completo vía LDAPS
```

### Insight

- LDAPS → mismos ataques que LDAP pero cifrado
- Si 389 rechaza conexión → probar 636 con ldaps://


## CONDICIONES CLAVE

- Anonymous bind → enumerar todo sin creds
- Creds válidas → dump completo con ldapdomaindump
- Descripciones de usuarios → revisar siempre por contraseñas
- adminCount=1 → cuentas privilegiadas históricamente
- Sin contraseña requerida → target para AS-REP Roasting
